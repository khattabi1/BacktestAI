# Institutional MQL5 Strategy Blueprint & MT5 MCP Operating Manual

This document defines the strict quantitative engineering standard for the **BacktestAI** autonomous agent mesh (`Muse Wonder` & `Muse Spark 1.3`) when generating, compiling, and testing institutional MQL5 Expert Advisors.

---

## 1. The 8-Block Quantitative MQL5 Blueprint Standard

Every Expert Advisor generated by the Quant Architect must implement the canonical 8-block blueprint:

### Block 1: Strategy Core Concept & Signal Logic
- Precise directional rules for BUY, SELL, and NEUTRAL states.
- Bar-close confirmation (`is_new_bar()`) to prevent intra-bar repainting and tick whipsawing.

### Block 2: Indicators & Mathematical Inputs
- Handles declared at global scope and initialized in `OnInit()`.
- Explicit handle validation: `if (h_indicator == INVALID_HANDLE) return INIT_FAILED;`.
- Indicator releases in `OnDeinit()` using `IndicatorRelease(h_indicator)`.

### Block 3: Dynamic Risk & Position Sizing
- Never hardcode fixed lot sizes without risk scaling.
- Fractional account risk formula: `Lots = (AccountBalance * RiskPercent) / (StopLossPoints * TickValue)`.
- Enforce broker volume constraints: `SymbolInfoDouble(Symbol(), SYMBOL_VOLUME_MIN)`, `SYMBOL_VOLUME_MAX`, `SYMBOL_VOLUME_STEP`.

### Block 4: Execution & Environmental Filters
- **Spread Filter**: `if (Ask - Bid > MaxSpreadPoints) { g_blocked_by_spread++; return; }`
- **Time/Session Filter**: Restrict entries to London/New York sessions.
- **Weekend / Rollover Buffer**: Block trading during high-spread rollover hours.

### Block 5: Trade Management & Trailing Engine
- Breakeven trigger: Move Stop Loss to Entry price once trade reaches `1.0R`.
- ATR-based dynamic trailing stop.
- Partial Take-Profit scaling if configured.

### Block 6: MQL5 Lifecycle Handlers
- `#property strict` at the top of every file.
- `#include <Trade\Trade.mqh>` using the standard `CTrade trade;` class.
- Adaptive filling mode detection (`SYMBOL_FILLING_FOK`, `SYMBOL_FILLING_IOC`, `SYMBOL_FILLING_RETURN`).

### Block 7: Mandatory Diagnostic Telemetry Counters
To enable real-time autopsy diagnostics when 0 trades are generated, every EA **MUST** declare and increment these global counters:
```mql5
ulong g_ticks_total        = 0;
ulong g_blocked_by_time    = 0;
ulong g_blocked_by_spread  = 0;
ulong g_signals_found      = 0;
ulong g_orders_placed      = 0;
ulong g_orders_rejected    = 0;
```

### Block 8: Autopsy Telemetry Dump in `OnDeinit()`
When the simulation ends or the EA is removed, the telemetry must be dumped to the terminal log:
```mql5
void OnDeinit(const int reason)
{
   PrintFormat("[DIAGNOSTICS] TotalTicks=%I64u | BlockedByTime=%I64u | BlockedBySpread=%I64u | SignalsFound=%I64u | OrdersPlaced=%I64u | OrdersRejected=%I64u",
      g_ticks_total, g_blocked_by_time, g_blocked_by_spread, g_signals_found, g_orders_placed, g_orders_rejected);
}
```

## 2. FastMCP Tool Execution Reference

The Quant Agent interacts with the MT5 portable worker fleet via these tools:

1. **`compile_mql5(ea_name)`**:
   - MetaEditor CLI compiles `MQL5/Experts/<ea_name>.mq5` -> `<ea_name>.ex5`.
   - Parses `.log` file for exact line numbers, warnings, and syntax errors.
   - Automatically synchronizes `.ex5` across `mt5_workers/shared_experts` and `worker_1..5`.

2. **`run_strategy_tester(ea_name, symbol, period, from_date, to_date)`**:
   - Generates dynamic tester INI in isolated worker directory.
   - Sets Unix timestamp date range in `terminal.ini [Tester]`.
   - Executes headless simulation with `Model=0` (Every Tick).

3. **`read_test_report(report_path)`**:
   - Extracts closed deals, Net Profit, Profit Factor, Max Drawdown, Sharpe Ratio, Sortino Ratio.
   - Extracts diagnostic telemetry counters for error autopsy.

4. **`copy_rates_range(symbol, timeframe, date_from, date_to)`**:
   - Fetches historical OHLCV bars directly from broker tick cache.
